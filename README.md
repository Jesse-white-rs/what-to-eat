# 🍜 今天吃什么

一个选择困难症终结者的纯前端静态网站，部署于 GitHub Pages。

## ✨ 功能

- 🎲 **一键随机选餐**：从你的菜谱库中随机抽一个，被选次数少的更容易被抽中（加权随机）
- 📝 **自定义菜谱**：自由添加菜名、店名、分类、价格和备注，支持随时编辑与删除
- 🗂️ **分类筛选**：按"正餐 / 快餐 / 小吃 / 饮品 / 夜宵"等自定义分类筛选
- 📜 **选择历史**：记录每一次的随机结果，可一键清空
- 💾 **伪前后端数据系统**：数据保存在与页面同级的 `data.txt`（JSON 字段）中，实现"伪前后端"架构

## 🏗️ 伪前后端架构说明

GitHub Pages 是纯静态托管，浏览器无法直接写服务器文件，因此本项目采用**伪前后端**模式：

| 层 | 角色 | 说明 |
|---|---|---|
| `data.txt` | 服务端数据库 | 与 `index.html` 同级的 JSON 文本文件，页面加载时通过 `fetch()` 读取 |
| `index.html / script.js` | 前端 | 读取、展示、增删改菜谱 |
| `localStorage` | 写库缓存 | 所有增删改先写入本地存储，实时生效 |
| 导出/导入 `data.txt` | 云同步通道 | 下载最新数据文件，替换仓库中的 `data.txt` 即完成同步 |

**数据同步流程**：在页面里做的所有修改都会保存在你的浏览器本地。点击页面底部的「💾 数据同步」→「下载 data.txt」获得最新数据文件，把它上传替换 GitHub 仓库根目录的 `data.txt`，即可让所有访客看到最新菜谱。

> ⚠️ 注意：`data.txt` 必须保持合法的 JSON 格式，且字段为 `{"version": 2, "dishes": [...], "history": [...]}`。

## 🚀 本地运行

直接用浏览器打开 `index.html` 即可（数据存储于本地浏览器）。更推荐使用本地静态服务器：

```bash
# 任选其一
npx serve .
python -m http.server 8080
```

## 🌐 在线访问

部署完成后访问：

```
https://<用户名>.github.io/<仓库名>/
```

```
└── .github/
    └── workflows/
        └── deploy.yml  # GitHub Pages 自动部署
```
